> 不碰临床账与留出段，不碰 `phase0/batch1_report.md/.html` 与两份预注册稿的锁定条款。
> 本文件在三组测算**全部开跑之前**写定；跑完要改只能另开一版。
> 出生证：创建日 2026-11-08 ｜ 依据代际：判据 v2 + 功效曲线 ｜ 最后实质修订 2026-11-08

## 0. 问题

批次一与对照实验的结论都指向同一件事：现有段长下，`0.2` 量级的真实相关看不见
（验证段 80% 检出线 `r=0.40`）。本文件只算「把它变成可判要付多少」，三选一：

1. **换频率**：把周频换成日频，样本变多，但自相关会吃掉一部分；
2. **缩命题**：不换数据，把否定结论改写成「排除 ≥ r」的上限；
3. **重排切分**：总跨度不变，验证段拉长、训练段缩短。

不改任何已有代码逻辑：`phase0/ruler.py` 的 `measure()` 与 `phase0/controls/run_power.py`
的注入/判定/内插函数原地复用，新脚本只做编排与单位换算。

## 1. 口径（三条路共用）

- 尺子：`ruler.measure`（52 点滚动 z → 段内配对 → 窗口峰值 → 循环平移零分布 → 块自助
  95% 区间），与 §7 同一把尺子。
- 判据：v2 每段 `2.5%`；主口径**远平移**（`P_far ≤ 2.5%` 且区间不含 0），严格双版并列。
- 注入：`run_power._one_block` 的同一混合公式 `lag = r·lead[t-k0] + sqrt(1-r²)·noise·(sd_lead/sd_noise)`，
  领先块的真实片段 + 噪声的圆周远平移，每次重复随机换块起点与平移量。
- `r` 网格 `0.10..0.50` 步长 `0.05`；检出线线性内插，网格外不外推。

## 2. 路径一（换频率）的参数与已知偏离

| 项 | 值 | 理由 |
|---|---|---|
| 日频领先序列 | FRED `DCOILWTICO` 日值 | 公开可得（本仓库已抓过一次） |
| 日频滞后/噪声序列 | Yahoo `UGA`（美国汽油基金）日线，备选 `RB=F` | 需实抓确认，不凭印象 |
| 段长（交易日） | 训练 `1480`、验证 `520` | 与 296/104 周同一日历跨度，只增加采样密度 |
| 滞后网格 | `k = 0..8`（单位：**行 = 交易日**） | 见下方 2.1 的跑前修正 |
| 窗口 | `[1,8]`（交易日） | 同上 |
| 注入滞后 | `k0 = 3` 交易日 | 与 `run_power._one_block` 的 `shift(K0)` 同一行数 |
| 远平移门限 | `far_min = 26` 交易日（尺子默认 `FAR_MIN`） | 同上 |
| 预热 / 段尾余量 | `52` / `13` 行 | 与周频同一组常数 |
| 每格重复 | 20 次 | 二项标准误最大约 ±8.9 个百分点；周频为 60 次（±6.5） |

### 2.1 开跑前修正（读代码后，非结果驱动）

原设计把日频的滞后网格设想为「周单位」映射（`k=3` 即 21 行、预热 260 行、`far_min` 130 行），
读 `run_batch1.seg_xcorr` 与 `ruler._pair` 后发现做不到：两处的**移位**是 `lag_z.shift(-k)`
（按行），只有**段尾裁剪**用 `Timedelta(weeks=k)`（按周）。周频下二者同义，日频下不同义。
要按周映射就必须改这两处代码，违反「不改任何已有代码逻辑」。

故改为：日频路径用尺子的**字面行数语义**——`k`、`WARM`、`far_min` 全部是「观测行数」，
与周频调用的数值完全相同，只把数据换成日频。代价是滞后搜索窗从「1–8 周」变成「1–8 个
交易日」，这是路径一必须与检出线一起读的结构性差异（写进 §8 的「主要代价」）。

`run_power._one_block` 唯一不能直接复用的地方是段尾：它按 `Timedelta(weeks=n_len-1)`
算终点。日频调用后由本脚本按行重算终点，其余（混合公式、块起点随机、噪声远平移）原样复用。

**已知偏离（必须与数字一起读）**：`ruler.measure` 的滚动 z 是「52 个观测」而非「52 周」，
日频下即 52 个交易日（约 2.4 个月），比周频的 52 周窄。这是尺子的字面参数不变、日历
含义变化；它可能留下更多低频水平波动，抬高零分布的 `N_eff` 损失。故日频结果按「同一把
尺子的行数语义」读，不与周频做点对点的日历等价宣称。

折算独立观测：用尺子返回的 `NullView.neff`（对零分布平移值做 `acf_tau` → `N_eff = N/τ`），
这是峰值统计量实际携带的独立信息量，不是名义样本数。

### 2.2 开跑前修正二（单任务实测后，未见过任何日频输出）

分阶段计时测得：日频单任务 `measure` 约 `97.8s`（训练 1480 行）、两段合计约 `128s`；
周频单任务 `11–39s`。同机实测可用并行度约 `4.7` 核（进程数再多只增加切换开销）。

原设计的日频网格 `[0.05, 0.08, 0.10, 0.12, 0.15, 0.20] × 20 次`=120 任务，
按此吞吐需 50 分钟以上。故下调为 **5 个网格点 `[0.10, 0.15, 0.20, 0.25, 0.30]` × 8 次**
（40 任务，约 18–20 分钟），理由：

- 日频 `N_eff` 大于周频，检出线预期低于周频 `0.40`，但不至于低到 `0.05` 附近；
- `8` 次重复的二项标准误在 `80%` 处约 `±14` 个百分点，对应 `r` 的读数误差约 `±0.03`，
  足以支撑「哪条路更划算」的比较，但不足以支撑精确阈值。

该下调与 §2 表中「每格重复 20 次」不符，以本节为准；两处不一致会在 §8 里再标一次。

## 3. 路径三（重排切分）的参数

总跨度固定 `400` 周（= 296 + 104，与现状同量级），只改两侧比例：

| 切分 | 训练 | 验证 |
|---|---|---|
| 现状基线 | 296 | 104 |
| 1:1 | 200 | 200 |
| 1:2（训练:验证） | 133 | 267 |

按段长跑同一注入网格，得到各段 `n` 下的检出线；不重跑现状基线（直接引用 §7 的 296/104 结果）。

**开跑后参数修正（非结果驱动）**：同机吞吐实测后，每格由 30 次降为 **20 次**（二项标准误在
80% 处约 ±8.9 个百分点），并保留 `baseline valid`（104 周）一段作为「新数据 + 同一把尺子能否
复现 §7 量级」的对照。`1:1` 与 `1:2` 两段各自独立取块（种子按段长区分）。

## 4. 路径二（缩命题）是纯算术

用 §7 已发布的检出线，不做新模拟：
- 现有段长的 80% 检出线：训练 `0.28`、验证 `0.40`；
- 50% 检出线：训练 `0.18`、验证 `0.28`。

「可声明排除的上限」取验证段 80% 线（保守）与 50% 线（宽松），并写明它只对本批尺寸成立。

## 5. 数据与留痕

日频原始件与派生件**不入库**（沿用 `phase0/controls/data/*` 的忽略规则），只把来源 URL、
抓取时刻、SHA256、行数、首末日期写进 `snapshot.json` 的 `sources`（新增键，不覆盖旧键）。
抓不到就把失败原因写进对照表，不换标的凑数。
