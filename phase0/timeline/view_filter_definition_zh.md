## 1. 为什么它是独立维度，不是 `is_event` 的子集

`is_event` 只回答「世界有没有变」；本维度回答「这条消息本身能不能让人直接看懂、有没有新东西」。

两者可以四向组合，而且都有实例：

| 组合 | 实例 | 说明 |
|---|---|---|
| `is_event=是` 且本维度「看」 | 抽样第 2 条（独立财务顾问报告） | 事件成立，标题也把事情说清了 |
| `is_event=是` 但本维度「不看」 | 抽样第 4 条（进展暨完成工商变更登记） | 作者明确说：**它是真事件，按 §1.3 判「是」没错，但我不看** |
| `is_event=是` 且本维度「判不了」 | 抽样第 7 条（财务顾问意见） | 事件性不争议，但标题说不清谁对谁，需翻前置文件 |
| `is_event=不是` | 抽样第 9 条（科创板 244 单，汇总） | 事件层已挡掉，本维度不参与 |

所以：**本维度不改变 `is_event`，也不从 `is_event` 推导**。组合结果只决定「默认展不展开 / 要不要人补一份前置文件」，不决定「算不算事件」。

## 2. 两条判准（一句话 + 布尔式）

### 2.1 自足（self-contained）

**一句话**：只看标题，能不能说出「谁（具名承担者）对谁/对什么（可指认对象）做了什么（实质动作）」——三个位置都不需要再打开另一份文件补齐。

**布尔式**：

```text
self_contained := named_actor(title) ∧ identifiable_object(title) ∧ substantive_action(title)
                  ∧ ¬reference_only(title)

reference_only := 标题的实质动作只出现在引述文件名内（《…》/「…」/""），
                  或标题只有「就某文件发表意见/说明」，而事实没有在引号外展开
```

- `identifiable_object` 不要求专名：具名主体 + 比例/数量/项目/子公司关系等可指认信息即可（见 §5 边界 2）。
- `substantive_action` 指交易、批复、处罚、任免、投产、政策生效等改变状态的动词；「发表意见/出具报告/作出说明」不算。

### 2.2 增量（increment）

**一句话**：标题陈述的是该事项自身的一次实质状态变化，而不是对既有文件的意见、提示/预告、程序登记、进展通报或成绩单汇总。

**布尔式**：

```text
increment := substantive_action_outside_quotes(title)
             ∧ ¬(opinion_only ∨ notice_only ∨ registration_only ∨ progress_only ∨ aggregate)

opinion_only       := 标题只表达「就《…》发表意见/出具报告/作出说明」
notice_only        := 提示性公告 / 预告公告 / 首次告知
registration_only  := 工商变更登记 / 备案 / 过户等程序性登记
progress_only      := 「…进展暨…」「进展公告」
aggregate          := 达 N 单 / 一览 / 汇总 / 盘点 / 成绩单式统计
```

引述规则：**《…》里的动作不算标题的断言**。第 7 条的「要约收购」在《山鹰国际控股股份公司要约收购报告书摘要》里面，所以不构成增量；第 2 条的「要约收购」在引号外，构成增量。

### 2.2.1 这套判法会说一句善意的谎（必读）

第 4 条（进展暨完成工商变更登记）被归为「无增量」，**但它其实有增量**——股权真的过户了，权利真的换了人。

把它判成「无增量」的真实理由不是「没有变化」，而是「这类事每天太多、**不稀缺**」。而「稀缺」不可客观判——它正是被否掉的重要度换了个说法。这里用**可判的体裁**（进展/登记）去代理**不可判的稀缺**，是**一次有意的近似**，不是一次客观测量。

所以：**不许把「无增量」写成客观事实，必须写成代理判断。** 这条判法会对某些条目说一句善意的谎——「没新东西」，而实际上有。第 4 条就是现成的例子。

落到实现与文案上：

- 字段与文档一律读作「按体裁代理，判为无增量」，不读作「客观确认无增量」；
- 展示层写人话时用「这类公告按惯例不展开」，不用「这条没有新信息」；
- 任何用本维度去论证「某事不重要」的用法都越界：本维度只说「这条消息按体裁不提供新读点」，不说「这件事不重要」。

### 2.3 为什么用这两条，而不是按体裁分

第 2 条和第 7 条都是中介机构文件，一个「看」、一个「视麻烦」。**按体裁分不开**。可分开的差异是：第 2 条的标题在引号外写明了「瀚启 要约收购 苏州建科院」，第 1、7 条只写「就某文件发表意见」。所以判的是**标题自足度**，不是文件体裁。

## 4. 与 `is_event` 组合后各格怎么读

| `is_event` | 自足 | 增量 | 读法 | 默认位置 |
|---|---|---|---|---|
| 不是 | — | — | 事件层已挡，本维度不参与 | `rejected` |
| 是 | 是 | 是 | 独立可读，且本条带来实质变化 | 候选展示（再按身份/主题过滤） |
| 是 | 是 | 否 | 读得懂，但本条只是意见/提示/进展/登记/汇总，没有增量 | 默认不展开（`no_increment`） |
| 是 | 否 | 是 | 有实质动作，但标题说不清谁对谁 | 判不了（`needs_source_doc`） |
| 是 | 否 | 否 | 同上；若连引述文件都没有，只是名词堆 | 判不了或默认不展开 |

注意「默认不展开」不是删除：条目仍在 `events.json`，只是不放进用户第一屏；用户可以按标记找回。**是否展示是视图层的决定，不是事件层的判定。**

## 5. 边界情形（允许判不了，别硬判）

1. **引号里的动作**：动作只出现在《…》/「…」/"" 内 → 不算标题断言；自足与增量都不据此判「是」。
2. **代称对象**：具名主体 + 可指认标的（比例/数量/项目/子公司关系）= 自足「是」；只有「公司/标的/项目」而无可指认信息 = 判不了。第 10 条属于前者，但它是本稿最松的一处（见 §7）。
3. **多动作标题**（「进展暨…」）：取主句（第一个完整命题）；主句是进展/登记 → 增量为「否」。
4. **拟议事项**（拟收购/筹划发行/预案）：增量为「是」，但必须带 `proposed` 标记，不与「已发生」同形（沿用 `event_definition_zh.md` §1.3）。
5. **汇总/成绩单**（达 N 单/一览/盘点）：增量为「否」；主体是集合词 → 自足为「否」。
6. **身份/主题不匹配**：机器不判。机器不得以「不是律师」「与主题无关」为由改判自足或增量；这两项只进用户配置。
7. **判不了要显式**：`needs_source_doc` / `ambiguous_object` / `ambiguous_actor` 都是合法输出，不许用「不是」代替。

| 标记 | 取值 | 含义 | 是否改变 `is_event` |
|---|---|---|---|
| `view.self_contained` | 是 / 否 / 判不了 | §2.1 | **否** |
| `view.increment` | 是 / 否 / 判不了 | §2.2 | **否** |
| `view.reason` | `needs_source_doc` / `notice_only` / `progress_only` / `registration_only` / `aggregate` / `opinion_on_document` / `ambiguous_object` / 空 | 落格原因，供展示层写人话 | **否** |

三条死线：

1. **不引入任何形式的重要度分值**：0–3、高/中/低、字母档、排序分都不许。第 4 条「不看」的理由是「这是流程登记」，不是「它不重要」；重要与否仍然不评。
2. **`view.*` 不是 `reject_codes` 的成员**，不得用来把 `is_event=是` 翻成「不是」。
3. **各格不排序**：展示顺序由时间或用户规则决定，不由本维度给权重。

## 8. 三个口子的裁决（2026-11-28 作者定案）

1. **判不了 → 不进待定池。** 单独一格 `needs_source_doc`；界面一行汇总「另有 N 条需要前置文件才能读懂」，可展开。
   理由：判不了是机器缺信息，不是要用户判断，不该占用户的手。
2. **体裁排除 → 机器判，配一个总开关。** 用户可一键「显示程序性公告」，默认收起。
   理由：体裁是信息结构问题、对所有人成立；但用户原话是「普遍不提供价值」，普遍 ≠ 全部，所以必须留总开关。
   **不许做成逐条配置。**
3. **身份未配置 → 默认展示。** 理由：默认展示的风险是可见噪声，默认隐藏的风险是用户不知道自己被藏了什么；可撤销的多，不可撤销的少。

这三条只决定**默认视图**，不改变 `is_event`，不引入任何重要度分值。

## 9. 这套判法最可能在哪儿出错

1. **引号剥离不全**：中文标题还有「」、""、（）嵌套；只剥《》会把文件里的动作当成标题断言（第 7 条立刻翻成「是」）。
2. **「可指认对象」的松紧**：第 10 条的「控股子公司少数股权」不是专名。严格按具名判会变成「自足否」，放宽就会放过一些说不清的标题——这是本稿最可能的误判带。
3. **体裁词表靠词面**：「关于…的进展公告」漏一个「进展」就判成增量是。
4. **多动作标题的主句边界**：靠标点切分，「进展暨…」与「…并…」容易切错。
5. **同形不同义**：「要约收购报告书」既可指收购方文件，也可指被收购方文件；自足只判「说不说得清」，不判「角色对不对」，角色颠倒不会被这一维抓住。
6. **`view.*` 被当成重要度用**：本维度是**代理判断**，会系统性地把「例行但真实的变化」判成「无增量」（第 4 条即例）。这个偏差**已知且接受**；但**不得**用这 10 条去反向调词表把它抹平——那会把开发集与真实流混在一起，让代理判断看起来像客观结论。一旦有人拿 `view.increment=否` 去论证「这件事不重要」，这一维就已经被误用成重要度了。
