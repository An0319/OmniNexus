# 中英术语对照（草稿）

> 创建日：2026-11-08 ｜ 依据代际：桌面壳 React 重构 + 界面文案外置 ｜ 最后实质修订：2026-11-08

这份表只做两件事：固定一个概念的中英名字，划清它**不能**被理解成什么。
它不定义概念本身——「主表 / 待选区 / 已剔除」的判据归 `phase0/timeline/` 的事件定义文档，状态码与判定口径归 `status-map`。本表复述的意义只为翻译时不走样，与判据冲突时以判据为准。

## 使用约定

- **状态码与数据值不入表**：`status`（`ok` / `partial` / `failed` …）、`verdict`（`hit` / `miss` / `undetermined`）、`reason_code`（`SOURCE_UNREACHABLE` …）是数据，不是文案，任何语言下都原样输出，不翻译、不改写。
- **一个概念一个译名**：同一概念在全表只有一行；代码里换个字段名不算换概念。
- **「不许被怎么理解」优先级高于「建议英文」**：译名可以换，边界不能动。

---

## 分档（去处，不是分数）

### 主表

- 建议英文：`Main list`（内部键 `primary`）
- 释义：已经判定是事件、且信息齐全，默认视图直接展示的那一份。
- 不许被怎么理解：不是「所有抓到的条目」，也不是「高分条目」；它按「是不是事件 + 信息全不全」分，不按重要性排名。

### 待选区

- 建议英文：`Pending`（界面标签可用 `Pending items`，内部键 `pending`）
- 释义：确实是事件，但值不值得看因人而异，机器不替用户定，放在一处可一键全收或全弃的地方。
- 不许被怎么理解：不是「待抓取」「正在处理」；也不是要用户主动去打开的抽屉或折叠菜单下的隐藏层。

### 已剔除

- 建议英文：`Filtered out`（内部键 `rejected`）
- 释义：判定不是事件（行情快照、研报评级、盘点、聚合页、传闻等），留档可查，但不出现在默认视图里。
- 不许被怎么理解：不是「抓取失败被源拒绝」，也不是「判定出错被丢弃」；被剔除的条目仍然完整保留，能查到为什么被剔除。

## 判定

### 判不了

- 建议英文：`Cannot judge`
- 释义：到了该下结论的时候仍下不了，而**为什么下不了**必须另看原因（缺数据 / 源不可达 / 算不出）。
- 不许被怎么理解：**不许译成 `undetermined`**——那个词把「数据不够」和「没对上」混成一件，正是要拆开的两件事；也不许译成 `unknown`（无法区分「没查」和「查了没结论」）、不许译成 `no data`（那只是其中一种原因）。

---

## 失败态（三种，不得合并成一句「暂无数据」）

### 缺数据

- 建议英文：`Missing data`
- 释义：到期了，但窗口里没有可用观测（一条都没有、清洗后为空、条数不够、窗口没覆盖到）。
- 不许被怎么理解：不能读成「这件事没发生」；数据缺失是观测侧的事实，不是结论。

### 源不可达

- 建议英文：`Source unreachable`
- 释义：连接、HTTP、解析或字段层面拿不到数据，属于消息源这一侧的问题。
- 不许被怎么理解：不是「没有数据」的同义词——源坏了不等于事实不存在；也不与「算不出」（定义本身无解）混用。分桶名可写作 `Sources unavailable`，但具体原因码仍原样展示。

### 算不出

- 建议英文：`Cannot compute`
- 释义：数据齐全、源也没问题，但定义本身在数学上无定义，算不出值。
- 不许被怎么理解：不是源的问题，不是数据缺失，也不等于「结果为 0」。

---

## 抓取结果

### 一份不完整的抓取

- 建议英文：`An incomplete run`（界面一句话：`Partial capture: this result is incomplete.`）
- 释义：只拿到一部分消息源，其余失败或缺失，因此这份结果不足以代表整段时间窗。
- 不许被怎么理解：不是「抓取失败」（全部失败才算失败），也不是「结果可信度打折但可以照读」——它必须显式标出缺了哪些，不许只在角落写一句。

---

## 人的东西

### 我的判断

- 建议英文：`My judgments`
- 释义：我登记下来、到期要用事先写死的判据去核对的那句话。
- 不许被怎么理解：不是「预测」「押注」「观点」——它不追求猜对市场，只追求「到期能不能按判据核出来」；也不许译成 `predictions` / `forecasts` / `bets`。

### 我的记录

- 建议英文：`My records`（单条可称 `a record`；内部文件名 `registry.ledger.jsonl` 保持原样）
- 释义：所有判断连同登记时刻、判据一起被冻结写下的那份文件，只增不改。
- 不许被怎么理解：不是「缓存」或「日志」；也不是可以事后编辑的草稿。用户可见文案一律叫「我的记录」，不叫「账本」。

---

## 内容单位

### 线索

- 建议英文：`Lead`
- 释义：从抓取结果里挑出来、可能值得进一步核的一条东西；是起点，不是结论。
- 不许被怎么理解：不是「已确认的事件」，也不是侦探意义上的 `clue`；被叫作线索不代表它就是真的。

### 事件

- 建议英文：`Event`
- 释义：满足硬定义的一条事实记录（有主体、有动作、有时间、有出处），可以被判据核验。
- 不许被怎么理解：不是「任何一条新闻」，也不是「热点」；不满足定义的一律进待选区或已剔除，不许为了凑条数放宽。
